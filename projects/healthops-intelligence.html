PROJECT 07 · FULL-STACK OPERATIONS DEMO

HealthOps Intelligence

A fictional operations dashboard exploring how a small facility can review appointments, staffing, stock, and data-quality signals in one local-first tool.

LOCAL BUILD · 18 TESTS PASSED · BROWSER REVIEW AND PUBLIC SOURCE REPOSITORY PENDING

Problem and audience

Small facilities may keep appointment and inventory information in separate lists. This demo gives an operations reviewer a single place to inspect synthetic records, make controlled changes, and see the audit trail.

Audience: junior software reviewers interested in API design, relational data, validation, and quality assurance.

Scope and safety

Every name, email, appointment, account and stock quantity is fictional. Emails use the reserved .invalid domain. There is no diagnosis, medication, or treatment data. This is not a clinical product and has no healthcare certification.

Features

  • Role-aware sign-in and administrator account-role controls.
  • Patient registry, appointment creation/state transition, and staff directory.
  • Inventory receipts/issues, low-stock reporting, and movement history.
  • CSV import/export with strict validation, transaction rollback, and spreadsheet-formula escaping.
  • Audit events, English/Spanish UI, responsive layout, and light/dark themes.
  • Daily appointment trend, median-absolute-deviation anomaly flags, and a transparent 28-day mean baseline.
  • Public-bind guard that forces remote instances into read-only role access.

Architecture and technology

Verified local implementation: Python standard-library HTTP API and static file server, SQLite, and browser-native HTML/CSS/JavaScript. The requested Angular/TypeScript, Express/Node, and PostgreSQL stack is not implemented in this version: package-registry access and Angular tooling were unavailable, and PostgreSQL server was not running. The OpenAPI contract and migration decisions are documented in the project source.

Run locally and verify

cd projects/07-healthops-intelligence
python3 api/server.py
# open http://127.0.0.1:8787
sh scripts/run_tests.sh

Seeded login: admin@healthops.local / DemoHealthOps!2026. Demo credentials are public by design; never use them for real data.

Verification: 13 API-handler integration tests, 2 Python data-quality tests, and 3 frontend-contract tests passed; Python compile and Node JavaScript syntax checks passed. Socket binding and browser rendering were blocked in the current sandbox, so visual/mobile checks remain open.

Analysis methods and limits

The trend compares the last 7 calendar days with the previous 7. Anomaly flags use a modified z-score from median absolute deviation with a 3.5 threshold. The next-week demand line repeats the prior 28-day average. These methods are transparent demonstrations only; no predictive accuracy is claimed and no staffing or clinical decisions should be based on them.

Case study and evidence

The repository includes an architecture diagram, entity model, OpenAPI contract, installation/security guides, user manual, test plan, and a case study with limitations. A real screenshot has not yet been captured. No mockup is presented as application evidence.

PROYECTO 07 · DEMO FULL-STACK DE OPERACIONES

HealthOps Intelligence

Panel operativo ficticio que explora cómo revisar citas, personal, existencias y señales de calidad de datos en una herramienta local.

VERSIÓN LOCAL · 18 PRUEBAS APROBADAS · PENDIENTE REVISIÓN EN NAVEGADOR Y REPOSITORIO PÚBLICO

Problema y público

Los centros pequeños pueden mantener citas e inventario en listas separadas. Esta demo ofrece a operaciones un sitio para revisar registros sintéticos, hacer cambios controlados y consultar la auditoría.

Público: personas que revisan perfiles junior y buscan ejemplos de diseño API, datos relacionales, validación y aseguramiento de calidad.

Alcance y seguridad

Todos los nombres, correos, citas, cuentas y cantidades son ficticios. Los correos usan el dominio reservado .invalid. No hay diagnósticos, medicamentos ni tratamientos. No es un producto clínico ni cuenta con certificación sanitaria.

Funciones

  • Inicio de sesión con roles y administración de roles de cuentas demo.
  • Registro de pacientes, creación y transición de estado de citas, y directorio de personal.
  • Entradas y salidas de inventario, informes de bajo stock e historial de movimientos.
  • Importación/exportación CSV con validación, rollback transaccional y escape de fórmulas de hojas de cálculo.
  • Auditoría, interfaz español/inglés, diseño adaptable y temas claro/oscuro.
  • Tendencia diaria, alertas de anomalía MAD y una línea base transparente con media de 28 días.
  • Protección al enlazar públicamente: fuerza el acceso de solo lectura.

Arquitectura y tecnologías

Implementación local verificada: API HTTP y servidor estático con biblioteca estándar de Python, SQLite y HTML/CSS/JavaScript del navegador. Esta versión no implementa la arquitectura solicitada de Angular/TypeScript, Express/Node y PostgreSQL: no había acceso al registro de paquetes ni herramientas Angular y el servidor PostgreSQL no estaba activo. El contrato OpenAPI y las decisiones de migración están documentados en el código del proyecto.

Ejecución y verificación

cd projects/07-healthops-intelligence
python3 api/server.py
# abre http://127.0.0.1:8787
sh scripts/run_tests.sh

Acceso sembrado: admin@healthops.local / DemoHealthOps!2026. Las credenciales de demo son públicas por diseño; nunca uses datos reales.

Verificación: pasaron 13 pruebas de integración del handler API, 2 de calidad Python y 3 de contrato del frontend; también pasaron compilación de Python y sintaxis JavaScript. El sandbox bloqueó sockets y renderizado de navegador, así que la revisión visual y móvil sigue pendiente.

Métodos y límites

La tendencia compara los últimos 7 días calendario con los 7 anteriores. Las alertas usan una puntuación z modificada basada en desviación absoluta mediana y umbral 3.5. La proyección repite el promedio de los 28 días previos. Son ejemplos transparentes, no se afirma precisión predictiva y no deben usarse para tomar decisiones clínicas o de personal.

Caso de estudio y evidencia

El proyecto incluye diagramas de arquitectura y entidades, contrato OpenAPI, guías de instalación y seguridad, manual, plan de pruebas y caso de estudio con limitaciones. Aún no se captura una imagen real. No se presenta una maqueta como evidencia de la aplicación.
