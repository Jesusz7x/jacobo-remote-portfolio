HealthOps Intelligence

A public, read-only demonstration of a fictional operations platform for reviewing appointments, staffing, inventory and data-quality signals. It presents a runnable Python web application with relational persistence and a bilingual browser interface.

Problem and audience

Small facility operations often need to review appointments, stock movements and record quality across separate lists. This project brings those administrative workflows and their audit trail into one demonstrable tool. It is intended as a software-engineering portfolio project, not for clinical work.

Implemented features

  • Executive dashboard, daily appointment trends and operational summaries.
  • Fictional patient registry, appointment workflows and staff directory with demo account roles.
  • Inventory receipts/issues, movement history and low-stock indicators.
  • CSV import/export with validation, data-quality checks and transactional rollback.
  • Role-based access, audit events, system settings, English/Spanish UI, responsive layout and light/dark themes.
  • Experimental anomaly flags using a median-absolute-deviation method and a transparent demand baseline using the prior 28-day mean.

Technology and architecture

Implemented technologies: Python 3.11+ standard library (HTTP server, API and processing), Python's built-in sqlite3, and browser-native HTML, CSS and JavaScript. SQLite uses constraints, foreign keys, indexes and transactions. Authentication uses PBKDF2-HMAC-SHA256 password hashes, hashed random session tokens, HttpOnly/SameSite cookies, role checks and login throttling.

Scope clarification: Angular, Express, PostgreSQL and browser end-to-end tests are not implemented in this version. The OpenAPI contract documents a future API boundary; it does not mean those technologies are in use.

Run and test

The repository documents the local demo accounts. Their credentials are intentionally public and must never be reused with real information.

Verification recorded in the project README: 13 API-handler integration tests, 2 Python data-quality unit tests and 3 frontend contract tests passed (18 total). The test suite dispatches API requests in-process because this build sandbox blocks socket creation. Python compilation and JavaScript syntax checks are also documented as passing. Live HTTP/browser rendering and visual/mobile review remain unverified.

Analytics and limitations

The trend compares the last 7 calendar days with the previous 7. Experimental anomaly flags use modified z-scores based on median absolute deviation with a 3.5 threshold. The next-week demand baseline repeats the previous 28-day average. These explainable demonstrations make no accuracy claim and must not inform clinical or staffing decisions.

Problema y público

Las operaciones de centros pequeños suelen revisar citas, movimientos de inventario y calidad de registros en listas separadas. Este proyecto reúne esos flujos administrativos y su auditoría en una herramienta demostrable. Es un proyecto de portafolio de ingeniería de software, no una herramienta para trabajo clínico.

Funciones implementadas

  • Panel ejecutivo, tendencias diarias de citas y resúmenes operativos.
  • Registro ficticio de pacientes, flujos de citas y directorio de personal con roles para cuentas demo.
  • Entradas/salidas de inventario, historial de movimientos e indicadores de bajo stock.
  • Importación/exportación CSV con validación, revisión de calidad y rollback transaccional.
  • Acceso por roles, auditoría, configuración, interfaz español/inglés, diseño adaptable y temas claro/oscuro.
  • Alertas experimentales de anomalías mediante desviación absoluta mediana y línea base transparente de demanda con el promedio de los 28 días previos.

Tecnologías y arquitectura

Tecnologías implementadas: biblioteca estándar de Python 3.11+ (servidor HTTP, API y procesamiento), sqlite3 incluido con Python, y HTML, CSS y JavaScript nativos del navegador. SQLite usa restricciones, claves foráneas, índices y transacciones. La autenticación usa hashes PBKDF2-HMAC-SHA256, tokens aleatorios de sesión almacenados como hashes, cookies HttpOnly/SameSite, permisos por rol y limitación de intentos.

Alcance: esta versión no implementa Angular, Express, PostgreSQL ni pruebas de extremo a extremo en navegador. El contrato OpenAPI documenta una frontera futura de API; no significa que esas tecnologías estén en uso.

Análisis y limitaciones

La tendencia compara los últimos 7 días calendario con los 7 anteriores. Las alertas experimentales usan puntuaciones z modificadas basadas en la desviación absoluta mediana y umbral 3.5. La línea base de demanda repite el promedio de los 28 días previos. Son demostraciones explicables sin afirmaciones de precisión y no deben guiar decisiones clínicas ni de personal.
