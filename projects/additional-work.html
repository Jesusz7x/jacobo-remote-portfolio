ADDITIONAL WORK · PROJECT DOCUMENTATION

Tools with a clear scope.

Business Sales Dashboard

Problem: make a small fictional sales dataset easier to inspect without hand-written KPIs. Audience: a small-business analyst reviewing an order export. Stack: static HTML/CSS/JavaScript; 24 deterministic synthetic orders.

Features: date/category/region filters, revenue/order/unit/average metrics, monthly totals, product ranking, sortable table, filtered CSV download, English/Spanish controls, and empty-state handling. Revenue is quantity × unit price; average order is revenue ÷ order count.

node projects/02-business-dashboard/dashboard.test.js

Code: projects/02-business-dashboard/. Limits: data is embedded demo data, USD is illustrative, no real customers, server, login, or external data source. Browser visual checks for this standalone page remain to be run by the owner.

Automation Toolkit

Problem: make repetitive file operations repeatable and reviewable for an office operator. Stack: Python standard library.

Features: top-level file organization by extension or UTC modification month, recursive SHA-256 duplicate reporting, regex rename preview, recursive inventory CSV, required-folder checks, flat CSV/JSON conversion, and optional JSONL error logging. It never deletes duplicates; mutation commands require preview/apply/confirmation and refuse known overwrites.

python3 tools/automation_toolkit.py --help
python3 tools/automation_toolkit.py organize /path/to/copy --mode extension

Code: tools/automation_toolkit.py. Limits: no recursive organize/rename, XLSX/PDF/rich conversion, or rollback if an operating-system error happens after a multi-file plan begins. Try it on a copy first.

Task Management API

Problem: expose a small task list through a documented JSON interface for local integrations. Audience: a developer learning API contracts and persistence. Stack: Python WSGI and SQLite standard libraries.

Features: create/read/update/delete, state and priority validation, due-date validation, bounded request bodies, search, status filtering, pagination, parameterized SQL, structured errors, and in-process WSGI tests.

python3 projects/04-task-management-api/task_api.py --db /tmp/tasks.sqlite3
python3 -m unittest discover -s projects/04-task-management-api -v

Code: projects/04-task-management-api/. Limits: it binds to loopback and has no authentication/TLS, so it is not intended for Internet exposure or multi-user production. The sandbox prevents a live socket smoke test.

Inventory Ledger

Problem: keep small-business quantities consistent and preserve a movement history. Stack: Python and SQLite.

Features: unique SKU, product edits, receive/issue movements, before/after balance audit, low-stock filters and summary, movement history, and product/movement CSV export. A transaction updates quantity and ledger together; an issue exceeding available stock is rejected.

python3 projects/05-inventory-system/inventory.py --db /tmp/shop.sqlite3 --help
python3 -m unittest discover -s projects/05-inventory-system -v

Code: projects/05-inventory-system/. Limits: no valuation/cost, multiple warehouses, user permissions, concurrent web access, or imports. Back up the local database.

Quality Assurance Lab

Problem: give a reviewer reproducible evidence of how the data cleaner, tracker, and automation tools are checked. Audience: engineering and QA reviewers. Stack: Python unittest plus Node's built-in test runner.

Includes a test plan, positive/negative/boundary cases, reproducible defect log, and execution report. All recorded defects were found during local implementation and fixed with regression tests; no customer incidents are claimed.

python3 -m unittest discover -s tests -v
node projects/02-business-dashboard/dashboard.test.js

Code and evidence: projects/06-quality-assurance-lab/. Limits: browser rendering, mobile/screen-reader behavior, and cross-browser checks are not automated here.

Panel de ventas

Problema: facilitar la revisión de un conjunto ficticio de ventas sin escribir indicadores a mano. Público: una persona analista de un negocio pequeño. Tecnologías: HTML/CSS/JavaScript estáticos; 24 pedidos sintéticos y deterministas.

Funciones: filtros por fecha/categoría/región, métricas de ingresos/pedidos/unidades/promedio, totales mensuales, ranking de productos, tabla ordenable, descarga del CSV filtrado, interfaz español/inglés y estado vacío. Ingresos = cantidad × precio; promedio = ingresos ÷ pedidos.

node projects/02-business-dashboard/dashboard.test.js

Código: projects/02-business-dashboard/. Límites: datos de demostración integrados, USD ilustrativo, sin clientes reales, servidor, inicio de sesión ni fuente externa. Aún falta una comprobación visual del navegador para esta página.

Kit de automatización

Problema: hacer repetibles y revisables las tareas frecuentes con archivos. Tecnologías: biblioteca estándar de Python.

Funciones: organización de archivos del nivel superior por extensión o mes UTC de modificación, detección recursiva de duplicados con SHA-256, vista previa de renombrado regex, inventario CSV recursivo, validación de carpetas, conversión simple CSV/JSON y registro opcional JSONL de errores. No elimina duplicados; los cambios requieren vista previa, aplicación y confirmación, y evita sobrescrituras conocidas.

python3 tools/automation_toolkit.py --help

Código: tools/automation_toolkit.py. Límites: organización/renombrado no recursivos, sin XLSX/PDF/documentos complejos ni reversión si ocurre un fallo del sistema operativo después de iniciar un plan de varios archivos. Pruébalo primero sobre una copia.

API para gestión de tareas

Problema: exponer una lista pequeña de tareas mediante una interfaz JSON documentada para integraciones locales. Público: desarrollo que aprende contratos API y persistencia. Tecnologías: bibliotecas WSGI y SQLite de Python.

Funciones: crear/consultar/actualizar/eliminar, validar estados, prioridades y fechas, limitar el tamaño de entrada, buscar, filtrar por estado, paginar, usar SQL parametrizado, devolver errores claros y probar WSGI en proceso.

python3 projects/04-task-management-api/task_api.py --db /tmp/tasks.sqlite3

Código: projects/04-task-management-api/. Límites: escucha solo en loopback y no tiene autenticación/TLS; no debe exponerse a Internet ni usarse en producción multiusuario. El sandbox impide probar un socket real.

Registro de inventario

Problema: mantener coherentes las cantidades y conservar el historial de movimientos de un negocio pequeño. Tecnologías: Python y SQLite.

Funciones: SKU único, edición de producto, entradas/salidas, auditoría de saldos anterior/posterior, alertas de bajo stock, consulta de movimientos y exportación CSV de productos/movimientos. Una transacción actualiza cantidad e historial juntos; rechaza salidas superiores a las existencias.

python3 projects/05-inventory-system/inventory.py --db /tmp/shop.sqlite3 --help
python3 -m unittest discover -s projects/05-inventory-system -v

Código: projects/05-inventory-system/. Límites: sin valoración/costos, múltiples almacenes, permisos, acceso web concurrente ni importación. Respalda la base local.
